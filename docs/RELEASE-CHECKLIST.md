# Чек-лист выпуска

Пункты выполняются сверху вниз. Невыполненный пункт указывается в заметках о выпуске в разделе «Проверки».

## Подготовка версии

- [ ] номер версии обновлён в `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` и `src-tauri/tauri.conf.json`;
- [ ] раздел «Не выпущено» в [CHANGELOG.md](../CHANGELOG.md) перенесён в раздел новой версии с датой;
- [ ] созданы заметки о выпуске `docs/releases/vX.Y.Z.md` по образцу предыдущих;
- [ ] версия и имя установщика обновлены в [README.md](../README.md) и [INSTALL-WINDOWS.md](INSTALL-WINDOWS.md).

## Автоматические проверки

- [ ] `npm ci`
- [ ] `npm run lint`
- [ ] `npm run typecheck`
- [ ] `npm run build`
- [ ] `npm run test:e2e -- --repeat-each=3`
- [ ] `npm run tauri:check:windows`
- [ ] `npm run tauri:test:windows`
- [ ] `npm run test:native-e2e`
- [ ] `npm audit --audit-level=high`
- [ ] `gitleaks detect --no-git --source src --redact`
- [ ] `gitleaks detect --no-git --source src-tauri/src --redact`
- [ ] `semgrep scan --config auto --error src src-tauri/src`
- [ ] `trivy fs --scanners vuln,secret,misconfig --severity HIGH,CRITICAL --ignore-unfixed .`
- [ ] workflow `Release quality` успешно завершён для коммита выпуска.

## Сборка и артефакты

- [ ] установщик собран командой `npm run tauri:build:windows` из чистого рабочего дерева на коммите выпуска;
- [ ] установщик из `src-tauri\target\release\bundle\nsis` скопирован в `artifacts\releases\current` под именем `UnixGram-Desktop-X.Y.Z-x64-setup.exe`;
- [ ] сформирован файл `SHA256SUMS.txt`;
- [ ] сформирован SBOM.

### Контрольные суммы

```powershell
Get-FileHash -Algorithm SHA256 ".\artifacts\releases\current\UnixGram-Desktop-X.Y.Z-x64-setup.exe"
```

Значение вместе с именем файла записывается в `SHA256SUMS.txt`. Файл публикуется рядом с установщиком.

### SBOM

SBOM в формате CycloneDX формируется для каждого выпуска на коммите выпуска, после `npm ci`:

```powershell
trivy fs --format cyclonedx --output artifacts\security\sbom.cdx.json .
```

Файл прикладывается к выпуску на GitHub рядом с установщиком и `SHA256SUMS.txt`. В репозитории он не хранится, потому что устаревает при каждом обновлении зависимостей.

## Проверка в Windows

- [ ] чистая установка под обычным пользователем;
- [ ] запуск, вход на сайте, выход и повторный запуск;
- [ ] лента, профиль, сообщения, публикация и подарки проверены на тестовом аккаунте;
- [ ] добавление, переключение и удаление дополнительного аккаунта;
- [ ] закрытие окна сворачивает приложение в трей, пункт «Выйти» завершает процесс;
- [ ] счётчик на значке в трее и уведомления Windows;
- [ ] глобальные горячие клавиши;
- [ ] статус в Discord при запущенном клиенте Discord;
- [ ] внешняя ссылка открывается в системном браузере только после подтверждения;
- [ ] удаление приложения не оставляет запущенный процесс.

Покупки и другие финансовые операции для проверки не выполняются.

## Доступность

- [ ] проверка axe не выявляет нарушений уровней `critical` и `serious`;
- [ ] все действия в окне настроек доступны с клавиатуры;
- [ ] окно настроек проверено вручную с программой экранного доступа NVDA.

## Публикация

- [ ] создан тег `vX.Y.Z` на коммите выпуска;
- [ ] к выпуску на GitHub приложены установщик, `SHA256SUMS.txt` и SBOM;
- [ ] текст выпуска соответствует `docs/releases/vX.Y.Z.md`; относительные ссылки заменены абсолютными;
- [ ] на странице выпуска указано, что клиент неофициальный;
- [ ] на странице выпуска указано, что установщик не подписан;
- [ ] в репозитории присутствуют `LICENSE`, `PRIVACY.md` и `SECURITY.md`.

## Цифровая подпись

Доверенного сертификата Code Signing у проекта нет, установщик публикуется без подписи. Когда сертификат появится, в чек-лист добавляются пункты:

- [ ] установщик и основной исполняемый файл подписаны доверенным сертификатом;
- [ ] подпись проверена командой `signtool verify /pa /v`.

Выпуск не помечается как стабильный, пока не выполнены пункты цифровой подписи и ручной проверки на реальном аккаунте.
