# Как помогать проекту

UnixGram Desktop развивается как независимый open source клиент сообщества. Если хотите помочь, лучше делать это предсказуемо и без потери контекста.

## Что присылать

- баг-репорты с шагами воспроизведения;
- предложения по интерфейсу и удобству;
- правки документации;
- улучшения стабильности, безопасности и сборки.

## Перед созданием issue

1. Проверьте, нет ли похожей задачи в [Issues](https://github.com/jutsu-dev/UnixGramDesktop/issues).
2. Уточните версию клиента, версию Windows и способ входа.
3. Если баг связан с входом, сессией или сообщениями, не прикладывайте cookie, токены, личные переписки и другие чувствительные данные.

## Перед pull request

1. Синхронизируйте ветку с `main`.
2. Опишите, что именно меняется для пользователя.
3. Если меняется интерфейс, приложите снимок окна или короткое видео.
4. Если меняется релизная логика, обновите связанную документацию.

## Минимальная локальная проверка

```powershell
npm run lint
npm run build
npm run test:e2e
```

Для Tauri-части дополнительно:

```powershell
npm run tauri:test:windows
```

## Хороший баг-репорт

- что ожидалось;
- что произошло по факту;
- как это повторить;
- на какой странице или во вкладке это случается;
- есть ли разница между темами, масштабом или режимом окна.

## Хорошее предложение

- какую проблему решает идея;
- где она должна появиться;
- что меняется для пользователя;
- есть ли примеры из самого UnixGram или другого клиента.

Спасибо всем, кто помогает делать клиент аккуратнее, стабильнее и удобнее.
